# Adaptive Sub-Edge Surface Reconstruction — Specification

## Product goal
Stock OrcaSlicer + Python plugin only.

Use Orca/ZAA first, measure residual error on finalized simplified extrusion geometry, then add the minimum extra surface material required to meet the configured tolerance.

## Canonical flow
Fresh Orca slice
-> ZAA if applicable
-> Orca path simplification
-> posSimplifyPath Analyzer
-> immutable SubEdgePlan
-> plugin preview
-> normal Orca G-code generation
-> psGCodePostProcess validation/injection
-> output

No custom Orca build is required for v1.

## Single source of truth
The same immutable SubEdgePlan drives:
- preview
- predicted metrics
- injection

Injector never re-optimizes geometry.

## Fresh-slice requirement
Orca does not re-fire posSimplifyPath hooks for cache-loaded plugin-final objects.

A printable export therefore requires a matching plan generated by a fresh slice in the current plugin load/session.

Missing plan => INJECTION SKIPPED, original G-code unchanged.

## v1 supported print domain
Printable injection requires:
- exactly one printable object
- exactly one printable instance
- exactly one ModelPart volume
- no NegativeVolume/ParameterModifier
- no multimaterial painting
- single tool/extruder
- no other active slicing-pipeline capability
- empty classic post_process script list
- outward/top-facing non-crossing target surface
- supported Orca version/profile/dialect
- validated coordinate frame
- 0.4 mm nozzle / PLA first calibration target

Analysis-only mode may inspect broader inputs but must not inject.

## ZAA baseline
The Analyzer reads actual post-ZAA/post-simplification 3D paths.

Plan metadata records:
- zaa_enabled
- observed non-planar/Z-contoured path statistics

It does not rely on a binary assumption that every eligible path was changed.

## Error-driven sub-edges
Candidate Z values are independently optimized:

Z0 < z1 < ... < zk < Z1

Fixed 1/2 or 1/3 division is not assumed.

Initial minimum adjacent path-Z design parameter: 0.08 mm for 0.4 mm nozzle, subject to local bead/support clearance and later calibration.

## Material model
Sub-edge quality is scored together with the unchanged lower/upper structural beads.

Sub-edge flow/width/height are part of the accepted candidate. Full standard-wall flow is not assumed.

Overfill is an error, not a free smoothing mechanism.

## Ordering
Accepted sub-edges do not cross.

For z_A < z_B < z_C, print A -> B -> C.

## G-code insertion
Insert at the structural layer boundary after the lower layer is complete and before the upper layer begins.

Execution policy:
1. preserve parser state
2. retract/travel at a validated safe Z
3. descend at the first supported start point
4. print sub-edges lower-Z first
5. after the highest sub-edge, move UP to the next structural layer Z
6. restore logical extrusion/feed/state expected by Orca
7. resume original G-code

Never restore Z downward through printed sub-edges.

## Plan matching
psGCodePostProcess has no live Print/object.

Injector uses current-session PlanStore + config/layer/geometry fingerprints and anchors.

Exactly one plan must fully match the exported G-code. Zero or multiple matches => skip.

## Preview
Orca standard viewer remains pre-post-process.

Plugin preview renders the exact immutable plan used by Injector.

Plan status is separate runtime metadata:
- PLANNED
- INJECTION PASS
- INJECTION SKIPPED
- INJECTION FAIL

## Injection safety
- stateful parser, no regex-only mutation
- all anchors validated before output generation
- no partial injection
- idempotent markers
- streaming temp-file writer + sanity pass + atomic replace
- original output preserved on failure
- absolute/relative E handled explicitly
- unknown/unsupported motion state in target interval => skip

## Architecture
All implementation follows ARCHITECTURE.md and accepted ADRs.

Any safety/architecture relaxation requires a new ADR first.
